## Research findings

- GitHub has merged roadmap PRs 1–7, including PR 6 (#814), but no PR, issue,
  or remote branch for PR 8 or later. PR 6 intentionally stops at a fake
  terminal report producer; its PR description and integration suite identify
  production `driveLoop` report emission as PR 8 work.
- The current engine already owns the durable loop and accepts injected model
  and registry dependencies. It currently selects the flat default registry
  regardless of `orchestrator_runs.agent_role` and completes every run directly.
- PR 7 already provides a role-filtered, fresh graph/context projection; PR 6
  already owns atomic domain report finalization. PR 8 should compose those
  boundaries rather than adding another engine, queue, or report store.
- Independent research review confirmed that `engine.ts` hardwires the flat
  registry and that `recovery-worker.ts` currently drops the claimed session
  generation while invoking that path. It identified both as required PR 8
  seams and found no schema prerequisite.

## Decisions

- Start with the next unblocked roadmap item (PR 8), rather than creating
  speculative PRs 9–19. PR 9 is a declared safety prerequisite for enabling
  live billable domain work.
- Root stays behavior-compatible: its definition uses the existing flat
  registry and root prompt. PR 14, not PR 8, owns activation of the root-only
  delegation surface.
- Domain definitions use the existing role registries and PR 7 fresh
  projections. The existing PR 6 report-finalization transaction remains the
  only completion write path; PR 8 does not add a second runtime or report
  persistence path.
- The role-definition/engine slice is implemented locally and is fail-closed:
  domain runs remain queued unless an injected test dependency explicitly
  enables them. Root runs keep the existing flat registry and prompt.

## Goal and acceptance criteria

Fix the async completion race that could lose or duplicate an orchestrator
resume when a provider job finished while the current worker was still parking
the accepted invocation. A durable dispatch lease remains the single turn owner,
and a raced wake survives until release without crossing workspace boundaries.

## Decisions

Async callbacks do not enter `driveLoop`. They wake the leased durable dispatch,
whose release transaction consumes a pending-wake marker. The database derives
`workspace_id` from `orchestrator_runs -> projects`; callers cannot supply or
rewrite tenancy. The wake and release RPCs are service-role only.

The original PR branch accidentally included narrative-context commits from PR
#776. The replacement branch was rebuilt directly from current `origin/main`
with only the async-resume implementation and its security/test hardening; the
unrelated commits and their reverts are absent from its ancestry.

## Changes

The engine reconciles terminal async jobs immediately after parking. Async tool
workers wake the durable queue, while the recovery worker claims the parked run
before another model turn. The wake migration preserves an active lease,
requeues on release when a wake raced, rejects cross-workspace dispatch state,
and restricts execution to `service_role`. A schema-contract regression test
pins tenancy derivation, grants, and pending-wake consumption.

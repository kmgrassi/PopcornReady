## Goal and acceptance criteria

Add the minimum production-ready foundation for migrating trusted, service-role
workflow RPCs into TypeScript transaction modules without changing any workflow
behavior in this PR:

- provide a small, lazy server-only Postgres pool and typed transaction helper;
- inject the local CLI database URL through the existing local wrapper;
- close the pool during API shutdown;
- define the authoritative Supabase/direct-Postgres boundary;
- enforce the current RPC target inventory so no new workflow RPC appears
  accidentally;
- exercise unit, local Postgres, and real API paths;
- publish a ready-for-review pull request.

## Decisions

- `DATABASE_URL` is optional until a direct transaction is invoked.
- Persistent production backends use a direct Supabase connection when
  supported, otherwise Supavisor session mode; transaction mode is not used.
- Direct connections are trusted server access and must not be used to emulate
  user-scoped RLS.
- Initial migrations are limited to existing service-role workflow RPC
  families, and require a least-privilege database role before cutover.
- The RPC boundary validator records 49 production-runtime targets and one
  test-sandbox-only target. The production count includes five calls in
  `domain-run-service.ts`, whose embedded NUL byte makes ordinary text searches
  undercount them. Database integrity, trigger, RLS, and search functions
  remain valid database functions.

## Blockers and risks

- A connection as `postgres` or another owner bypasses RLS and most ordinary
  grants. No production workflow moves onto this path until a dedicated,
  least-privilege API database role exists.
- Production must provide a session-capable connection string; transaction-mode
  poolers are incompatible with session-level behavior and prepared statements.

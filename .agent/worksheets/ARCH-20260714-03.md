## Goal and acceptance criteria

Extend the proposed creative-director/domain-agent architecture so a creator
can request a standalone Image, Video, or Soundtrack through product UI and API
without starting a full production.

Acceptance criteria:

- “Standalone” remains a normal project-scoped, graph-backed request.
- Image and Video reuse Visuals; Soundtrack reuses Audio. No new runtime or
  session per product kind is introduced.
- Root-origin and creator-direct work share one serialized session per
  project/domain while preserving origin-specific causation and recipients.
- The API is discriminated, server-scoped, idempotent, authorized, and gated
  before billable work.
- Direct questions, blocked prerequisites, follow-ups, cancellation, outputs,
  and selection movement have explicit semantics.
- The UI is agent-directed, observe-first, accessible, and consistent with the
  product interaction/design system.
- The PR roadmap covers genuine standalone media primitives and separates the
  required direct track from the optional root-hierarchy cutover.
- The change is validated, independently reviewed, and published to the
  existing ready-for-review PR.

## Decisions

- Standalone creation means independent of the full creative-director flow,
  not independent of a project, authorization, budget, provenance, or graph.
- There is one persistent session per `(project_id, domain)`. Image/Video are
  Visuals task kinds; Soundtrack is an Audio task kind.
- Every assignment has exactly one trusted origin: `creative_director` with a
  root run/action or `creator_direct` with authenticated request causation.
- Reports have origin-specific recipients. Direct work never wakes a root or
  finalizes a delegation action.
- Direct paid work uses a two-phase quote/confirmation gate with actor, request
  digest, approved maximum, one-use token, and bound idempotency key.
- Direct outputs enter the immutable project asset pool and never move a
  production selection unless explicitly targeted, pinned, and transactionally
  revalidated.
- Generic image/video primitives and a freeform soundtrack mode are preferable
  to fabricated storyboards, beats, timeline slots, or legacy data.
- Asset Studio is one outcome-based creation workspace with one primary action,
  cost proposal, observe-first progress, provenance, and Request Changes. It
  does not expose internal agent cards or raw provider controls.
- Gate 0 governs the creative-director cutover only. PRs 2–13 deliver shared
  foundations and standalone creation; PR 14 onward is hierarchy-gated.

## Blockers and risks

- Shared sessions require visible queueing and strict origin/join/pin isolation
  so a direct experiment cannot invalidate an active production assignment.
- Existing production-shaped media tools may not express genuine standalone
  outcomes; the implementation must add graph-native modes rather than fake
  relational production structure.
- Direct API authorization and proposal confirmation are security and cost
  boundaries, not optional UI polish.

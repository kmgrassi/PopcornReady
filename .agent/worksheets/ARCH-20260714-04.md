## Goal and acceptance criteria

Update the specialist-agent orchestration scope with an evidence-backed
recommendation to reuse the current data model instead of introducing parallel
domain-specific persistence.

Acceptance criteria:

- The scope names every existing table/service that can be reused.
- `agent_sessions` is the only new domain-specific table; one general
  `action_assets` relation replaces unenforced UUID-array attribution for all
  tools.
- A finite domain assignment is an extended `orchestrator_runs` row.
- A typed `done | blocked | question` result is a unique terminal `actions`
  row, not a new report table.
- Existing dispatch, gate, idempotency, job, cost, asset, edge, and selection
  records remain authoritative.
- The plan explains session serialization, trusted origins, continuation,
  parent wake-up, output attribution, and direct approval without redundant
  foreign keys.
- Generic standalone image semantics are corrected without fabricating an
  anchor or keyframe.
- The roadmap and scenario/acceptance language use the revised model
  consistently.
- The documentation is independently reviewed, validated, committed, tagged,
  pushed, and opened as a ready follow-up PR.

## Decisions

- Add one `agent_sessions` identity/continuity table with a unique
  `(project_id, domain)` key.
- Extend `orchestrator_runs` for agent role, session sequence, task kind/spec,
  trusted origin, parent/continuation links, and domain runtime states. The run
  itself is the finite assignment.
- Keep primitive invocations in `actions`; emit one schema-marked
  `domain_report` action per domain run and enforce uniqueness with an index.
- Derive every child action's session/role/origin through
  `actions.orchestrator_run_id`; do not stamp redundant session/assignment
  columns onto every action.
- Reuse `orchestrator_dispatches` and make its claim transaction session-aware
  rather than adding a domain queue.
- Reuse `orchestrator_run_gates`, `actions.proposal`, `idempotency`,
  `model_call_costs`, the credit ledger, and existing cancellation/recovery
  paths for creator-direct work.
- Reuse `jobs` and the generated-assets internal service for image, video, and
  soundtrack provider execution.
- Add a general `action_assets` relation with composite same-project foreign
  keys, input/output direction, role, and ordinal. Dual-write and assert the
  legacy action UUID arrays during compatibility; do not add
  `domain_assignment_outputs`.
- Add `jobs.action_id`, preserve `assets.created_by_action_id`, typed
  `asset_edges`, and `selections`, and enforce same-project integrity through
  the complete session/run/action/job/asset chain.
- Allocate session sequence and active ownership atomically. Fence workers,
  callbacks, report finalization, and selection writes with a durable session
  claim generation copied onto jobs; reserve transient dispatch-lease checks
  for worker-owned transitions.
- Insert the immutable terminal report, terminalize the child run, advance the
  versioned session summary, release ownership, apply any parent delegation,
  and wake that parent in one idempotent transaction.
- Upgrade the existing idempotency helper to atomic reservation/consume and add
  compare-and-set provider-job claim; reuse the current tables.
- Extend existing gates with typed subject, actor/request digest, approved
  maximum, expiry, and a hashed one-use confirmation token. Reserve/settle
  budget atomically through current run/cost/credit records.
- Make raw sessions, runs/tasks, actions/reports, jobs, gates, and actor/request
  metadata owner/service-only; public projects receive sanitized projections.
- Derive dispatch workspace from its run's project and reject cross-workspace
  mismatch. Keep shared sessions permanent: cancel only causally linked root or
  creator-direct runs, continuations, and jobs.
- Add a generic graph image kind because the current mapping coerces generated
  images into `anchor` or `keyframe`. PR 10 owns the additive end-to-end enum,
  constraint, type, mapping, embedding, and projection migration while
  preserving explicit production kinds. Continue using `clip` for generated
  video and `audio_track` for soundtracks.

## Changes

- Added a source-to-reuse table covering runs, actions, dispatches, gates,
  idempotency, jobs, costs, assets, edges, selections, and generated-assets.
- Recast finite assignments as domain-role `orchestrator_runs` and typed
  outcomes as unique immutable `domain_report` actions.
- Replaced proposed domain-specific assignment/report/output persistence with
  one `agent_sessions` table and one system-wide `action_assets` relation.
- Added transactional sequence/claim/report/wake semantics, lease fencing,
  atomic idempotency and job claim, gate/budget constraints, cross-project
  integrity, and raw-control-data privacy requirements.
- Assigned the generic standalone-image graph-kind migration end to end to the
  Visuals PR and preserved explicit production image kinds.
- Updated creator-direct API, UI projection, scenarios, rollout gates,
  non-goals, merge ownership, and definition of done to use session/run/action
  identities consistently.

## Independent reviews

- Research checkpoint: completed. It confirmed that existing runs/actions are
  viable only with same-project constraints, immutable report finalization,
  private raw-control RLS, atomic idempotency/job claims, and stronger gate
  binding. It recommended a general relational action/asset join because
  Asset Studio requires roles, order, SQL queries, and foreign keys.
- Plan checkpoint: completed. It required atomic session sequence/claim,
  lease-fenced callbacks and writes, one transactional report/summary/wake
  transition, own-run versus descendant spend semantics, and an end-to-end
  generic-image migration owned by one PR.
- Implementation/document checkpoint: completed. It required durable session
  claim generations for callbacks after transient dispatch leases expire,
  dispatch/run/project workspace integrity, and run-scoped rather than
  permanent-session cancellation. All three blockers were incorporated.
- Wrap-up checkpoint: completed after the callback/session fencing, dispatch
  tenancy, run-scoped cancellation, validation, and parent-PR status updates;
  approved with no remaining blocker.

## Blockers and risks

- `orchestrator_runs` currently assumes one flat root history; every query and
  projection must become role-aware before child runs are enabled.
- The current dispatch claim is run-aware but not session-aware; serialization
  and late-worker fencing must be enforced transactionally across origins and
  media waits.
- `actions.output_asset_ids` is an ordered UUID array without relational role
  metadata or foreign keys. The general `action_assets` migration must avoid a
  permanent dual source of truth.
- Public-project RLS currently exposes raw orchestration records; the hierarchy
  cannot ship until sanitized projections replace that access.
- Current idempotency and provider-job launch paths can race across API/worker
  instances; the existing tables need atomic reservation and compare-and-set.
- Existing generated image mapping uses production-specific graph kinds, so a
  standalone-image path cannot ship until the generic kind is added end to end.

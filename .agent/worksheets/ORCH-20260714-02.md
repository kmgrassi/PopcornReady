## Decisions

- `agent_sessions.id`, `orchestrator_runs.id`, and `actions.id` remain the
  canonical identities. `DomainReportActionId` aliases the existing action ID;
  it does not introduce a report identity.
- Public domain-run identity is exactly `sessionId` plus `runId`.
- `DomainTask.v1` is a four-way union that binds domain, task kind, and allowed
  output kinds to one
  trusted origin/recipient route. Direct Audio kinds cannot enter Visuals,
  direct Visuals kinds cannot enter Audio, and a creator recipient cannot be
  paired with a root origin.
- Persisted task/report params do not repeat their enclosing session, run, or
  report action IDs. Internal envelopes join params to those canonical records;
  the public identity remains only `sessionId` plus `runId`.
- Response-recipient objects carry only the discriminant. Causation IDs are
  derived from the trusted origin rather than copied into a second object that
  could disagree.
- Every creator-direct task requires confirmed approval context; its
  domain-bound output union prevents Visuals from authorizing `audio_track` and
  Audio from authorizing visual outputs.
- Runtime transport states are separate from the only agent-authored outcomes:
  `done`, `blocked`, and `question`. `succeeded` means the terminal report action
  is already durable.
- Creator-direct proposal state is orthogonal to the finite-run state. Billable
  work becomes queued only after explicit confirmation.
- The new architecture record accepts the standalone domain foundation while
  keeping the creative-director hierarchy, its root ownership, and its two-level
  limit conditional on Gate 0.
- No active principle in `docs/NORTH_STAR.md` is amended. Only stale tool counts
  and their hand-maintained list are removed.
- Runtime app smoke is not applicable: this PR changes shared compile-time
  contracts and documentation only, with no API, worker, database, or web path.

## Goal and acceptance criteria

Implement trustworthy loading, progress, recovery, and terminal-state feedback across the generation run, dashboard activity, and project overview surfaces. Active work with unknown provider progress must be indeterminate; known item counts may be determinate. The UI must expose elapsed time and last activity, distinguish running/waiting/recovering/blocked/failed/partial/video-ready states, preserve failed-stage history during recovery, and never say a video is complete without a playable export artifact. Disabled output affordances must explain why no video is available.

## Decisions

- Preserve the existing generation status vocabulary and `completionKind`; do not add a parallel status enum.
- Treat missing percentages as unknown rather than coercing them to `0` or `50`.
- Preserve historical failed tool stages while selecting the newest running stage as the current activity.
- Require a ready video export asset with a playable source for video-ready copy and output links.
- Add orthogonal activity metadata (`working`, `waiting_on_job`, `recovering`) and `currentToolName` so the UI can explain non-linear execution without inventing a new lifecycle.
- Stop guessing a next stage or ordinal from the fixed eight-stage model; autonomous tools can re-enter prerequisites and the stage set is sparse.

## Blockers and risks

- Orchestrator tool execution is non-linear, so a fixed eight-stage percentage is not truthful.
- Workspace run summaries do not currently join action artifacts; dashboard loading copy must avoid claiming video completeness or synthetic percentages.

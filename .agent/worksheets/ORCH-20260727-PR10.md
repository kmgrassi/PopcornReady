## Decisions

- Stack the change on `codex/specialist-pr9-budget-runtime`; PR 10 does not own
  root routing, creator UI, Audio activation, or root cutover.
- Keep the flat root registry unchanged. The dedicated Visuals registry owns
  the six existing visual production primitives plus the two standalone
  generated-asset wrappers and exposes the narrow subset allowed by each
  Visuals task kind.
- Run standalone generation through the canonical generated-assets service and
  durable job lifecycle. Providers, models, minor policy, content hashes,
  immutable references, actions, and cost records remain server-owned.
- Standalone outputs remain pooled. Video edits do not implicitly move every
  selection that references a source asset.
- Activate only the Visuals role in this PR. Audio remains behind its existing
  gate for PR 11.
- Add generic graph `image` with separate enum and constraint/trigger
  migrations. Preserve all explicit production role mappings; only an
  otherwise-unclassified standalone still maps to `image`.
- Thread task scope and `sessionClaimGeneration` through the rich-tool bridge,
  enforce stable targets before side effects, and require a pinned authorized
  source plus exact content fingerprint for direct video edits.
- Use a role-aware runtime allowlist at every start/resume/definition boundary;
  production recovery enables `visuals` only and proves `audio` remains queued.
- Partition the model-visible registry by trusted task kind: standalone
  image/video/edit runs see one tool each, while production/revision sees the
  six established Visuals primitives.
- Validate a fresh trusted target scope before reserving the invocation action,
  then carry that scope and task through the rich-tool bridge. Model-supplied
  hashes never confer authority.
- Keep domain video edits and image regeneration pooled unless a later,
  explicitly pinned transactional selection workflow owns the move. PR 10
  reports `changedSelections: []` because every claimed domain media path is
  pooled; non-empty reporting belongs to that later transactional workflow.
- Keep claimed domain anchor, keyframe, and clip completions pooled as well.
  Session claims fence provider work but do not authorize a late selection
  append; the legacy flat-root jobs retain existing selection behavior.
  In-session recovery resolves pooled prerequisites only from immutable
  creation actions attributed to the exact finite run and stable beat/anchor.
- When a failure contains both local and cross-domain recovery candidates,
  preserve the cross-domain blocked outcome so it cannot disappear into a
  local retry loop.

  then identified six plan-critical gaps: unwired target guards, a dropped
  session-claim generation at the rich-tool bridge, missing Visuals-only
  recovery activation, the breadth of generic-image mappings, missing generic
  minor policy, and unsafe implicit selection replacement during video edits.
  The plan incorporates each finding. No files were changed by the reviewer.

  pre-invocation scope enforcement, truthful selection reporting, exact trusted
  edit pins, explicit task-kind registry partitions, and deterministic mixed
  recovery precedence. The second required parse-once input preparation before
  action persistence. The approved design adds a side-effect-free driver
  `prepareInput`: the rich parser and trusted policy run once, canonical input
  is persisted only after success, and estimate/execute consume that same
  value. No files were changed by the reviewer.
- Implementation: approved after three resolution passes. The reviewer first
  found target widening, action/claim drift, late regeneration checks, a weak
  cross-origin fixture, and label-only escalation coverage; each was corrected
  with trusted target injection, pre-side-effect exact-claim checks, locked
  regeneration preflight, a real preserved asset, and executable
  blocked/question paths. A later pass caught unsafe late selection appends;
  claimed domain anchor/keyframe/clip jobs now remain pooled. The final pass
  caught the resulting prerequisite gap; exact-run, stable-identity pooled
  lookup now preserves anchor → keyframe → clip recovery without selection
  writes. The reviewer approved the final implementation with no findings.
- Wrap-up: approved after one resolution pass. The reviewer required
  origin-safe empty `changedSelections`, a real exact-run pooled-prerequisite
  integration, accurate offline-versus-live decision-eval evidence, and one
  worksheet correction. Final review found no remaining scope, safety, testing,

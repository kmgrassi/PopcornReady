## Goal and acceptance criteria

Implement PR 6, "Turn-boundary dispatch, reports, and origin-specific
completion" (`docs/scopes/specialist-agent-orchestration-prs.md`), on top of
merged PR 5 (#813, domain-session store + claim fencing) and PR 7 (#795,
target-scope guards + compaction CAS):

1. One internal domain-run service (`domain-run-service.ts`, no index
   aggregator) + root-only `delegate_visuals`/`delegate_audio` adapters
   registered ONLY in the dormant creative-director registry. Server-derived
   trusted origin/scope only; creator-direct public routes are PR 12.
2. Single-transaction dispatch creation (idempotency reservation, session
   sequence allocation, task-bearing finite run, required gate, existing
   dispatch enqueue). Replays return the same identities.
3. Domain-wait state distinct from media-job/approval waits, wired through
   engine, store, and run projection.
4. Single-transaction idempotent turn finalization: immutable report action +
   `action_assets`, child terminalization, session-summary CAS, active
   ownership release (durable claim-generation advance), root delegation
   apply, exactly-one parent dispatch wake. Creator-direct completion: no
   parent mutation, no wake.
5. Continuation semantics: blocked/question closes the run; the answer is a
   fingerprinted one-use successor (`continues_run_id`, pins, new sequence).
   Attempt/cycle, depth, per-root child, report, continuation, turn limits.
6. Extended dispatch claim: earliest eligible confirmed sequence, session row
   lock/reserve, one active finite run per session across origins, queued
   state visible, media-wait ownership retention, durable claim-generation
   CAS so a reclaimed worker cannot commit late.
7. Origin-isolated queue/supersession policy + fences for cancellation,
   inline completion, reclaimed dispatches, duplicate callbacks, supersession,
   and late reports.
8. Transport boundary only: fake domain report producer in lifecycle tests;
   production driveLoop report emission is PR 8.

## Decisions

- **Catalog membership with a production/dispatch split.** `delegate_visuals`
  and `delegate_audio` join `TOOL_CAPABILITY_CATALOG` (typed registration
  requires it) with `surface: "dispatch"`, appended after the legacy 18 so
  display orders are unchanged. New `PRODUCTION_TOOL_NAMES` /
  `DISPATCH_TOOL_NAMES` / `isDispatchToolName` keep every flat surface
  (default registry, driver stubs, flat eval scenarios, tool-test batteries,
  bridge stubs) on the production vocabulary — nothing user-visible changes
  in production. The dispatch adapters are registered only by
  `createRootToolRegistry` (dormant).
- **One additive migration** (`20260727153000_turn_boundary_domain_dispatch.sql`)
  because the creation/finalization transactions and the session-aware claim
  cannot be expressed through PostgREST atomically. It composes with (does not
  fork) `allocate_agent_session_sequence`, `claim_agent_session_run`,
  `release_agent_session_run`, and `wake_orchestrator_dispatch`.
  `claim_orchestrator_dispatches` is dropped/recreated (return set gains
  session claim columns; clean break per the no-legacy rule).
- **Deterministic run identity from the idempotency key.** The service derives
  the run id from sha256(scope, key); a concurrent duplicate collides on the
  run/idempotency PK, the loser's transaction rolls back atomically, and one
  service retry lands in the replay branch returning the winner's identities.
- **Wake inside the finalization transaction.** The durable parent wake is the
  dispatch-row upsert performed by the same transaction that wins the terminal
  transition (extends completeDomainRun's wake semantics into the atomic
  path); the service exposes only a post-commit observability hook.
- **Root domain-wait.** `orchestrator_runs_wait_reason_shape` now admits
  `wait_reason = 'domain'` on a waiting ROOT run (the creative director parked
  on a delegated child); domain runs still must name their wait; everything
  else stays null. Engine `park(run, r, "domain")`, resume claim clears it,
  and the run projection reports `waiting_on_domain`.
- **Bounce guard.** DB-side per-root child and continuation-chain limits
  (errcode 54000) plus a service-side requirement-exhaustion check (a
  requirement blocked twice in one root family refuses further dispatches),
  so two domains cannot bounce one unmet requirement indefinitely.
- **PR5's `completeDomainRun` is left intact** as the store-level completion
  contract; `finalizeDomainTurn` is the transactional turn-closing path that
  PR 8 will call. The RPC also crash-heals a PR 5 append-then-crash window.

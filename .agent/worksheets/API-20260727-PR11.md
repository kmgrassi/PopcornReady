## Decisions

- Keep the canonical Audio vocabulary at `generate_audio` and
  `fit_audio_to_picture`. `soundtrack_create` and `audio_create` are trusted
  `DomainTask.v1` modes, not new tool names.
- Leave the flat default registry behavior unchanged. The persistent Audio
  session receives task-bound definitions from its own registry/profile.
- Standalone generation uses a single-track branch over the existing
  generated-assets service. It does not require or fabricate a plan, beat, or
  timeline slot and does not append a selection.
- The Audio profile reloads the graph projection and enforces exact trusted
  targets immediately before tool work; prompt text never grants authority.
- Fit critiques are supporting evidence, not `audio_track` outputs. A fit-only
  run may report an exact same-project track already named by the task target or
  preserve pins, while arbitrary existing assets remain forbidden.
- The generated-assets inner action remains the canonical provider/storage/cost
  and asset-creator record. The outer Audio action remains the model-visible
  wrapper/batch action; both retain the finite run/project link.
- Delivery, voice, warmth, bounded rate, mix, and timing with exact words
  preserved are Audio-local. Wording, facts, character intent, or spoken
  meaning changes terminate with `question` to the task-derived recipient.
- A genuine audio revision must mint the next immutable version in the source
  lineage with a source edge. This PR never moves a selection implicitly;
  targeted selection reconciliation remains a separate pinned operation.

## Changes

- Added a task-bound Audio prompt and registry profile under the unchanged
  canonical `generate_audio` and `fit_audio_to_picture` names.
- Added explicit project/beat/asset/timeline-item generation targets and
  fail-closed graph-scope/preserve-pin guards at the tool boundary.
- Added single-track narration/dialogue/music/sound execution over the existing
  generated-assets service. Standalone requests read no plan and write no
  selection; production requests persist the plan/brief/script inputs they use.
- Added current-picture-aware fit validation and critique provenance.
- Added immutable audio revision minting in the source lineage with fresh
  storage identity, serialized version allocation, and no selection update.
- Added exact-script/source-transcript enforcement and spoken-meaning/picture
  mismatch escalation guidance.
- Beat-targeted speech first proves that the current plan's `script_draft`
  graph edge names the current script, then resolves only the matching script
  scene by exact id or unique normalized title; reordered or otherwise
  ambiguous scenes fail closed.
  Fit/revision operations require exact trusted targets or pins, and revision
  source readiness is checked before provider execution.
- Added typed delivery presets that map to provider voice settings without
  altering spoken text, plus cleanup for a revision object if lineage minting
  fails.
- Audio revisions derive their immutable subtype from trusted provider settings
  and asset role; a model-selected content kind cannot turn music into speech,
  speech into music, or cross another recorded subtype.
- Follow-up review fixes keep standalone `audio_create` non-spoken until a
  trusted immutable script/text contract exists, so model-supplied words cannot
  become narration or dialogue. A persisted failed fit now deterministically
  becomes the origin-routed picture-versus-meaning question even if the model
  attempts to return `done`.
- Added focused decision scenarios, tool/worker/fit/completion tests, migration
  contract coverage, and a Supabase-gated generated-assets revision test.

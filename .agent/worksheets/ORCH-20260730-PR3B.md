## Goal and acceptance criteria

Implement the PR 3B video executor adapters behind the durable proposal
lifecycle introduced in PR 2.

- Beat, asset, and project targets dispatch only through their matching
  executor into one bounded, idempotent Visuals child run.
- The child assignment preserves exact required-output bindings and every
  approved asset, selection, and story pin.
- Canonical `generate_clip`, `edit_video_asset`, and `generate_video_asset`
  tools produce immutable assets under the child session claim.
- Child provider primitives reserve proposal-family budget before execution;
  terminal domain reports derive exact primitive, reservation, and output
  causation for the lifecycle callback.
- Outputs stay pooled. PR 5 owns production registration and atomic selection
  application.

## Research

- PR 2 exposes `RerunKindExecutor`, exact required-output bindings, child
  budget reservation, and callback fences while leaving the production
  registry intentionally empty.
- Canonical video creation already converges on immutable generated-asset jobs.
  Those jobs write graph inputs, reserve and settle deterministic cost keys,
  and keep outputs pooled when invoked under a run claim.
- The existing `generate_clip` tool skips an already selected clip, which is
  correct for initial generation but wrong for selective revision. Under a
  trusted `visuals_revision` child task it must generate the exact requested
  beat from its pinned keyframe and leave the result pooled.
- `edit_video_asset` already defines the correct `edited_from` graph edge and
  empty selection result; its request construction should be shared with the
  adapter.
- PR 3C owns the shared child-provider budget admission and terminal domain
  callback plumbing. PR 3B must use that contract instead of adding a parallel
  root-owned provider or callback path.

## Decisions

- Dispatch one bounded Visuals child per lifecycle executor group. The
  lifecycle idempotency key is also the durable child-dispatch identity.
- Return only the child handle from the adapter. Provider actions, generated
  assets, and settled reservations are child-run primitives discovered by the
  terminal domain callback.
- Never apply or rewrite the parent work dispatch action from the adapter.
  PR 2 `completeWorkTransaction` remains the sole atomic application boundary.
- Split beat clips, content-aware edits, and standalone generation into
  distinct executor IDs so semantic target mismatches block before dispatch.
- Never move a selection from the adapter or canonical domain job.

## Goal and acceptance criteria

Make long-running generation observable enough that creators see truthful progress and operators can distinguish active provider work from a stalled async job without waiting ten minutes.

- Persist and project real job progress timestamps and item counts for async generation tools.
- Add structured lifecycle logging around anchor generation and orchestrator resume handoff.
- Never infer 100% for a grouped stage while any grouped tool is still running.
- Avoid naming a completed stage as currently in progress while the orchestrator chooses its next tool.
- Show calm creator-facing progress, explicit slow/stalled states, and progressive admin diagnostics.
- Cover projection, worker, and browser behavior with targeted tests and run the affected app path.

## Decisions

- Keep polling; do not introduce WebSockets or a second state vocabulary.
- Treat durable job progress timestamps as the source of real activity. Recovery-sweeper writes are operational heartbeats, not creator-visible progress.
- Reuse the existing Supabase `jobs` table and its `progress` JSONB; do not extend the process-local JSON store as the production source of truth.
- Add diagnostics through the existing generation-run projection, with creator-safe fields and server-gated admin-only depth in the UI.
- Derive `normal`, `slow`, and `possibly_stalled` attention states conservatively; elapsed time alone never marks a job failed.

## Changes

- Added a tenant-scoped Supabase job gateway and migrated async storyboard,
  anchor, keyframe, clip, audio, edit, and export workers away from the
  process-local JSON job store.
- Added meaningful progress, heartbeat, provider, item-count, retry, and
  operator diagnostic projections with conservative slow/stalled attention
  states.
- Added creator-facing stage activity, grouped-stage progress fixes, truthful
  transition copy, and collapsed admin-only diagnostics to the run progress UI.
- Added lifecycle logging around anchor generation and orchestrator resume
  handoff.
- Added atomic tenant-scoped idempotency, patch-merge/terminal-safe job updates,
  and a service-only `public.jobs` RLS boundary so execution envelopes cannot be
  read or forged through direct Supabase access.
- Added conservative crash handling: stale queued work can replay from a
  validated typed envelope, while stale running provider work terminates with a
  recoverable error instead of risking duplicate billable calls.
- Updated the jobs, generation-progress, and E2E coverage documentation.

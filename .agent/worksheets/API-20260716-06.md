## Goal and scope

Replace process-local HTTP idempotency locking with a PostgreSQL-backed
reservation/consume lifecycle. This PR is limited to request idempotency;
provider-job claim fencing and generated-asset provenance remain separate PR 5
continuations.

## Decisions and changes

- Add service-role reservation, renewal, completion, and abandonment RPCs on
  the existing `idempotency` table, using a lease token to fence stale writers.
- Replace the in-process mutex with a typed store adapter that polls active
  reservations, replays completed responses, rejects digest conflicts, and
  atomically reclaims expired leases.
- Use PostgreSQL wall-clock time after lock acquisition so lock contention cannot
  write an already-expired lease.
- Treat renewal as best-effort. Always attempt token-fenced completion after a
  successful producer; only the durable token predicate determines ownership.
- Add tests for concurrent replay, null responses, conflicts, expiry, renewal
  success/error/false outcomes, reclaimed tokens, and an env-gated PostgreSQL
  race; add migration-contract coverage and document `idempotency_in_progress`.

## Goal and acceptance criteria

Reduce avoidable GitHub-hosted runner usage without weakening meaningful
runtime coverage:

- superseded Web E2E and Railway verification runs stop consuming runner time;
- Markdown-only and `.agent/**`-record-only changes do not start Web E2E;
- successful Web E2E runs do not upload an unused report artifact;
- stuck Web E2E jobs have a bounded runtime;
- API, web, and shared-package changes continue to run Web E2E.

## Decisions

- Keep both pull-request and `main` Web E2E triggers. Main has no required
  status checks, so removing post-merge coverage would be premature.
- Keep API and shared-package changes in scope because Playwright starts the
  real Express API and imports workspace packages.
- Do not cancel Supabase workflows; interrupting a database mutation is unsafe.
- Prefer cancellation, narrow documentation ignores, a timeout, and
  failure-only artifacts over reducing browser/project coverage.

## Changes

- `.github/workflows/web-e2e.yml`
  - ignores Markdown/agent-record-only changes on both PR and `main` events;
  - cancels superseded runs by PR number or branch ref;
  - caps the smoke job at 15 minutes;
  - uploads Playwright reports only on failure.
- `.github/workflows/deploy-api.yml`
  - cancels obsolete exact-SHA verification when a newer `main` push arrives;
  - isolates non-`main` manual dispatches by full ref so they cannot cancel
    production verification before their job-level gate skips them.
- `scripts/validate-github-actions-policy.test.mjs`, `package.json`, and
  `scripts/agent-validate.mjs`
  - add a local policy test and run it in every agent validation scope.
- E2E and Railway documentation now describe the runner policy, required-check
  caveat, artifact limits, and latest-`main` verification semantics.
- `apps/web/e2e/README.md` now begins with seven discoverable summary lines.
- `.agent/feedback/CI-20260730-01.md` records the reusable workflow lesson.

## Independent reviews

### Research

Independent reviewer confirmed that Web E2E dominates Actions usage, warned
that API/package changes are genuinely in scope, and recommended PR/ref
concurrency, failure-only artifacts, narrow documentation ignores, and
latest-commit Railway verification. The reviewer advised against removing
`main` E2E until branch protection requires the PR check and blocks bypasses.

### Plan

Independent reviewer approved the bounded plan after requiring two
clarifications now reflected in the implementation:

- workflow path filtering must be replaced with a successful no-op before Web
  E2E becomes a required check;
- the local test enforces repository workflow policy but does not claim to
  validate the complete GitHub Actions schema.

The reviewer also confirmed the PR/ref concurrency key, 15-minute job-level
timeout, failure-only artifact semantics, latest-`main` Railway cancellation,
and non-cancelable Supabase boundary.

### Implementation

Independent reviewer found one P2 test-quality issue: the initial policy test
required the two approved ignore patterns but would have allowed an extra
runtime ignore pattern. The test now extracts both live `paths-ignore` blocks
and requires each list to equal exactly `["**/*.md", ".agent/**"]`.

After that finding was resolved, the workflow policy tests, actionlint, lint
fix, full scoped agent validation, Web E2E, and PWA E2E all passed. The reviewer
reported no workflow-semantic or safety regressions. Actual GitHub event
filtering and cancellation remain observable only after the PR runs.

### Wrap-up

## Blockers and risks

- GitHub path filters skip the entire workflow when all files match the ignore
  list. The ignore list must remain limited to non-runtime documentation and
  agent records.
- Railway verification cancellation assumes production health should track the
  latest `main` commit, matching Railway's native latest-deploy behavior.

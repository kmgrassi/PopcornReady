## Goal and acceptance criteria

Make storyboard review the required stopping point for prompt/video generation: the orchestrator creates the brief, story, script/plan, and complete beat storyboard panels, then waits for an explicit user continuation before keyframes, clips, assembly, and export. The Storyboard page must clearly explain the review state and offer one accessible continuation action.

## Decisions

- The server, not a client checkbox or `runThrough` flag, owns the post-storyboard stop.
- Treat the user continuation as a permitted approval/gate action, not a direct content mutation.
- Defer required scene-level visual anchors: the current scene wireframe is optional/disposable and does not form a prerequisite for beat panels or keyframes. It needs its own asset/tool/conditioning contract before it can honestly become a required review layer.

## Changes

- Entry-point runs create only an `after:generate_storyboard` gate, including clients that send legacy `reviewGates`, `stopAfter`, or `runThrough` fields; those fields cannot stop before the board.

- Added focused API projection/continuation coverage, a durable engine-resume test, and Storyboard-page browser coverage; updated generation policy, scope, and E2E inventory documentation.

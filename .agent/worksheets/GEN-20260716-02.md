## Goal and acceptance criteria

Fix the production 10-second video path that reaches keyframe generation but is
rejected by Ideogram because the request contains more than one
`character_reference_images` part.

- Ideogram v3 requests never send more than its supported single character
  reference image.
- The first caller-ordered reference is preserved; later generic references are
  not submitted to Ideogram's single character-reference field.
- Other providers retain their existing multi-reference behavior.
- A focused test inspects the multipart request and proves the provider limit is
  enforced before the network boundary.
- The relevant API application path and required repository validation pass.
- An open, non-draft PR contains the implementation, documentation, worksheet,
  and feedback record.

## Decisions

- Ideogram v3's official generate contract accepts one
  `character_reference_images` file. Enforce that constraint inside the
  provider adapter because workspace-default provider resolution happens after
  the keyframe job is queued.
- Preserve only the first caller-ordered generic reference for Ideogram. Current
  keyframe calls place visual anchors before the storyboard structural
  reference, but the generic path list does not encode semantic priority or
  role; do not claim more than caller ordering guarantees.
- Do not remap later references to `style_reference_images` or switch to remix:
  later entries can be additional characters, locations, or structural sketches,
  and those changes need a typed role-aware provider contract.
- Keep requested-reference provenance unchanged in this bounded hotfix. Record
  the difference between requested and effective provider inputs as follow-up
  work rather than expanding the production fix.

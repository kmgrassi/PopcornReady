## Goal and acceptance criteria

Address all unresolved review threads on PR #814:

1. A root resuming after a child `blocked` or `question` report receives the
   typed report payload and recovery guidance.
2. The bounce guard rejects only a continuation that retries its own exhausted
   blocked requirement; unrelated sibling dispatch remains possible.
3. Canceling a domain run atomically terminalizes the run, releases/fences the
   session claim, and cancels causally linked active jobs.

## Decisions

- Keep the immutable `DomainReport.v1` on its child `domain_report` action and
  project it into the parent delegation action's schema-marked recoverable
  error. `done` remains `applied`; `blocked`/`question` become `failed`, so
  the resumed root receives both ordinary recovery guidance and the complete
  typed report (including question options/fingerprint).
- Derive the bounded retry requirement inside `create_domain_run_dispatch`
  from the root-origin continuation's persisted predecessor report. The RPC
  performs its idempotency replay branch first, locks the root to serialize
  admission, then counts only matching blocked requirements. No caller-supplied
  retry hint can bypass the limit.
- Add `cancel_domain_run` to the unmerged PR 6 migration. It locks run then
  session (the finalization order), terminalizes, releases/increments the
  claim generation, and cancels causal active jobs in one service-only
  transaction.

## Goal and acceptance criteria

Restore the production Supabase migration queue so the
`root_execution_profile` schema reaches production and orchestrator run creation
can succeed. Prevent another duplicate migration version from reaching
`supabase db push`.

Acceptance criteria:

- every file in `supabase/migrations` has a unique 14-digit version;
- the previously unapplied generic-image migration retains its ordering before
  dependent generic-image migrations;
- the migration workflow runs a clear duplicate-version preflight;
- a targeted regression test proves duplicate versions fail and unique versions
  pass;
- the API application path and required repository validation pass;
- the implementation, documentation, worksheet, and feedback record are
  committed, tagged, and published in a ready-for-review PR.

## Decisions

- Treat this as a migration-history collision, not a reason to remove the new
  API column or restore a retired schema surface.
- Rename only the unapplied duplicate migration. Do not edit or rename the
  already-applied `20260727180000_domain_run_failure_finalization.sql`.
- Keep the generic-image enum migration before its dependent constraint and RPC
  migrations.
- Add one dependency-free Node preflight shared by local validation and the
  migration deployment workflow.
- Reject malformed SQL migration names as well as duplicate versions, and test
  the CLI entrypoint so workflow wiring—not only a pure helper—is covered.
- Converge the opposite collision history with a fresh-version, idempotent
  replay of the complete domain finalizer DDL. Never repair or reinterpret the
  already-recorded `20260727180000` history.

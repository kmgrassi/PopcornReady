## Decisions

- Extended the harness additively: new modules (`gate0-report.ts`,
  `gate0-scenarios.ts`, `hierarchy-fixture.ts`) beside the untouched
  `scenarios.ts`/`run-decision-eval.ts`, per the merge-conflict hygiene rules.
  The existing `evals:orchestrator` script and live test are unchanged.
- Classification taxonomy per sampled decision: `acceptable`, `wrong_tool`,
  `premature_done` (done while work remains), `unnecessary_turn` (tool call
  after completion), `repeated_failed_call` (re-choosing the tool that just
  failed). The last failed prior result is derived from scenario state, not a
  parallel annotation, so recovery scoring stays observable.
- The hierarchy simulation is decisions-only by construction: fixture tool
  definitions carry name/description/schema and no `execute`; the root surface
  is built from the dormant `createRootToolRegistry()` (same composed
  descriptions production would use) plus hand-written
  `delegate_visuals`/`delegate_audio` fixture definitions; visuals/audio
  surfaces come from their dormant registries.
- Exported the production system prompt from `orchestrator/model.ts` as
  `ORCHESTRATOR_SYSTEM_PROMPT` so the fixture-surface real-model adapter uses
  the exact production decision prompt (only the tool surface differs between
  compared architectures).
- Real-model runs stay opt-in exactly like the existing harness: key-gated
  report script (`evals:gate0`) and skip-gated live tests. Added a `--fixture`
  offline mode to the script so the report plumbing can be exercised end to
  end with zero model calls.
- Gate-0 record lives at `docs/scopes/gate-0-decision-record.md` with the
  measured-dimension table, a proposed (not yet agreed) material-improvement
  threshold, and the decision field recorded as PENDING with run
  instructions; blocking semantics per the scope (defer blocks PR 14 only;
  PRs 10–13 standalone track independent).

### Review response (PR #791, Codex reviewer — three inline findings)

1. **P1: paired scenario matrix for the gate comparison.** Previously the flat
   side scored 33 scenarios and the hierarchy side 9 different ones, so the
   threshold comparison was not apples-to-apples. Added
   `evals/paired-projection.ts`: a deterministic, capability-catalog-driven
   projection of every flat scenario onto the hierarchy surface (consecutive
   applied visuals/audio leaf results collapse into one dispatch result
   carrying the union of stable asset ids; failed leaves map their remedies
   into dispatch vocabulary; a trailing in-domain self-heal failure projects
   onto that specialist surface with its in-domain history). The runner scores
   the SAME 33 paired scenarios (same ids/samples/provider) on both surfaces;
   the hand-written `HIERARCHY_SCENARIOS` run as labeled
   `hierarchyDiagnostics` excluded from the gate comparison.
   `gate-0-decision-record.md` now states the comparison is paired-scenario.
2. **P2: dispatch failures dropped from hierarchy routing context.** Added
   `buildFixtureRoutingContext` in `evals/hierarchy-fixture.ts`: production
   `buildRoutingContext` output is used verbatim for real-tool signals
   (special-case hints included), and only results whose tool name is a
   fixture dispatch get the equivalent local extension (completedTools,
   latestFailure, suggested-recovery nextToolHint). Production
   `buildRoutingContext` semantics are untouched; the real-model fixture
   adapter now uses the wrapper.
3. **P2: --json output not parseable.** Extracted the CLI composition into
   `evals/gate0-baseline-runner.ts` with injectable out/err writers: JSON mode
   emits exactly ONE top-level document
   (`{ mode, comparison, samplesPerScenario, pairedScenarioCount, flat,
   hierarchy, hierarchyDiagnostics }`) on stdout and routes every banner to
   stderr; the script is now a thin arg parser. The gate record documents the
   `--json > gate0-baseline.json` workflow.

   New deterministic tests cover all three behaviors (projection coverage/
   correctness, routing-context preservation + production parity, single-JSON
   stdout + stderr banners + paired totals): 26/26 pass, still zero network.

## Decisions

- Extended the harness additively: new modules (`gate0-report.ts`,
  `gate0-scenarios.ts`, `hierarchy-fixture.ts`) beside the untouched
  `scenarios.ts`/`run-decision-eval.ts`, per the merge-conflict hygiene rules.
  The existing `evals:orchestrator` script and live test are unchanged.
- Classification taxonomy per sampled decision: `acceptable`, `wrong_tool`,
  `premature_done` (done while work remains), `unnecessary_turn` (tool call
  after completion), `repeated_failed_call` (re-choosing the tool that just
  failed). The last failed prior result is derived from scenario state, not a
  parallel annotation, so recovery scoring stays observable.
- The hierarchy simulation is decisions-only by construction: fixture tool
  definitions carry name/description/schema and no `execute`; the root surface
  is built from the dormant `createRootToolRegistry()` (same composed
  descriptions production would use) plus hand-written
  `delegate_visuals`/`delegate_audio` fixture definitions; visuals/audio
  surfaces come from their dormant registries.
- Exported the production system prompt from `orchestrator/model.ts` as
  `ORCHESTRATOR_SYSTEM_PROMPT` so the fixture-surface real-model adapter uses
  the exact production decision prompt (only the tool surface differs between
  compared architectures).
- Real-model runs stay opt-in exactly like the existing harness: key-gated
  report script (`evals:gate0`) and skip-gated live tests. Added a `--fixture`
  offline mode to the script so the report plumbing can be exercised end to
  end with zero model calls.
- Gate-0 record lives at `docs/scopes/gate-0-decision-record.md` with the
  measured-dimension table, a proposed (not yet agreed) material-improvement
  threshold, and the decision field recorded as PENDING with run
  instructions; blocking semantics per the scope (defer blocks PR 14 only;
  PRs 10–13 standalone track independent).

## Lesson

The old deployment check answered only whether Railway reported something that
looked like the pushed commit. It could accept a SHA prefix and could not prove
that Netlify, the same-origin proxy, the API artifact, and the required database
schema belonged to one coherent release. Separate immutable web/API envelopes
plus one credential-free verifier make each independent deploy surface
observable without adding production authority.

The initial ordered-prefix migration model conflicted with the repository's
documented `--include-all` workflow. A canonical required-version set preserves
rollback compatibility when the applied ledger contains extra lower or higher
additive migrations. The local integration test was essential: a static SQL
assertion could not prove that `popcorn_api` can read `version` while table-wide
and every other column remain denied.

The production-build route test also exposed that indirect `import.meta.env`
access can retain development lazy imports. Vite must see the direct `DEV`
property to fold it out, while Node tests need a `typeof import.meta.env` guard.
Running both the Node suite and an actual preview build is what covers that
boundary.

## Follow-up

Keep production mutation disabled until the later sandbox identity, control
plane, cleanup, and provider-budget PRs land. Separately address the pre-existing
phone-width overflow in the development design-system harness; it was observed
during required manual inspection but is unrelated to release identity.

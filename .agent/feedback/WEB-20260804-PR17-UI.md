## Lesson

The API portion of PR 17 had already landed, but the web clients still discarded
the hierarchy and rendered the old tool pipeline. A rollout audit therefore has
to trace the response through every client boundary and every long-running UI,
not stop at server types or endpoint tests. Run detail and restored Studio used
different state paths, so both required explicit integration and browser proof.

The hierarchy becomes useful only after translating persistence vocabulary into
creator outcomes. Visuals and Audio, ready output counts, and plain queued or
blocked explanations belong in the default view; finite runs and primitive
actions are diagnostic depth. Putting current work before the approved-plan
recap was also essential at mobile width, where static context otherwise pushed
the actual production state below the first viewport.

The creator-safe hierarchy and operator debugging surface share a response but
not an audience. Replacing the primitive pipeline must not accidentally remove
authorized diagnostics; extracting the existing collapsed disclosure lets both
legacy and hierarchy-backed runs retain it without leaking operator density into
the Creative Director panel. Summary copy also needs explicit state priority:
parallel lane order is storage order, not evidence of which work is current.

## Follow-up

Keep Asset Studio's creator-direct recipient UI separate. If later API work adds
new specialist domains or richer report metadata, extend the typed projection
and domain copy together rather than leaking task kinds or internal identifiers
into the creator surface.

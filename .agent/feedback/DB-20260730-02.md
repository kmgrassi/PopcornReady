## Lesson

A service-role query against an empty table cannot prove RLS, and a fake domain
reader cannot prove the production Supabase query names. The useful stack is
layered: statically reject retired runtime relations, execute production query
construction and mapping without a database, then use concrete local rows to
separate service access from owner/outsider/anonymous RLS behavior.

Dynamic `.from(table)` calls weaken a retirement validator even when their
current callers are safe. Literal branches keep the runtime target inventory
greppable and force a future retired target to appear directly in the AST.

Auth integration fixtures own two identities: `auth.users` and `public.users`.
Cleanup must remove both and must continue after an earlier cleanup failure.

## Follow-up

Run `pnpm db:contracts:test:local` after Docker/local Supabase is responsive.
For each future direct-Postgres transaction, keep role capability coverage
operation-specific rather than broadening `popcorn_api` into a generic reader.

## What helped

The thread-aware review read isolated one precision bug, while the Netlify API
showed that four failed statuses were one deploy failure with one exact
secret-scan match. That kept the fix focused instead of treating every status as
an independent test failure.

## Friction and improvement

Recovery used `updated_at` as a compare-and-swap token after mapping it through
`Date.toISOString()`. Future database leases and claims should keep time-based
eligibility checks inside PostgreSQL, where timestamp precision is preserved.
Security tests should avoid credential-shaped literals unless the deployment
scanner has an explicit, reviewed fixture mechanism.

## What helped

Parallel ownership split cleanly across durable worker telemetry, API
projection, and progress UI. The independent plan review caught the local JSON
store boundary before implementation, and the integrated implementation review
then tested whether the combined system actually recovered across process
restarts rather than merely persisting status.

## Friction and improvement

The first durable-job implementation stored state in Supabase but still launched
workers only through process-local promises. Future plans should define the full
recovery contract up front: versioned replay input, an ownership lease, stale
claim behavior, atomic idempotency, and who can read or mutate the execution
envelope. Compatibility tests should also include job IDs created by the
storage mechanism being replaced. Provider work that lacks end-to-end
idempotency should not be replayed after it has started; terminalize it as a
recoverable failure instead of risking duplicate paid calls.

A broad API test glob unintentionally selected opt-in live model tests during
integration. The run was stopped when live calls appeared, then replaced with
an explicit file list. Future generation validation should always start from
the documented targeted list and name every test file when live suites share a
directory with unit tests.

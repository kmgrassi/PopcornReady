## Observation

The initial request described reducing the number of GitHub Actions used per
run, but recent history showed that marketplace action steps were negligible
compared with browser-test and obsolete polling runner time.

## Improvement applied

Optimize the expensive workflows around latest-commit semantics: cancel
superseded browser/deployment verification, skip non-runtime Markdown and agent
record changes, bound browser jobs, and retain artifacts only for failures.
Guard the cancellation boundary with a local policy test so Supabase mutations
remain serialized.

## Follow-up

If Web E2E becomes a required check, replace workflow-level path filtering with
a classifier/no-op job before enabling the requirement. Re-measure runner usage
after enough PR and `main` runs accumulate; only then consider splitting the
browser matrix or removing the post-merge run.
